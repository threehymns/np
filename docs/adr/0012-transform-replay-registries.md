# Shared registries rebuild from replayed transforms

Every registry that multiple plugins contribute to (commands, settings layers, keybindings, icons, and future equivalents) rebuilds by replaying registered transform functions in order from an empty initial value on every change, following the design OpenCode describes for its State abstraction. Plugins describe their changes; the host decides when to apply them. This makes refresh, ordering, and removal deterministic: a removed plugin's transforms are dropped and the registry rebuilds without them, and a data refresh cannot silently undo another plugin's contribution. Registry transforms must be pure functions of their inputs and repeatable; side effects, UI mounting, and document mutations are not registry transforms and follow the hook and lifecycle rules instead.
